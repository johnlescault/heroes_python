## 1. What this project is

A kid-friendly **gamified Python learning game** in the style of *Heroes of Might
and Magic*. A child writes Python in `my_hero.py` (opened in **Thonny**) to
plan a hero's turn. A **pygame** window shows the adventure map, previews the
planned path live whenever the file is saved, and executes the turn when the
player clicks **COMMIT TURN**.

Concepts taught (in order): sequential statements → function calls with
arguments → coordinates → `for` loops (bridge building) → planning across
multiple turns/state.

Platform: Linux (user `joey`), Python 3.12, `pygame`, a `.venv` in the project
root. Windows is also considered (DPI-awareness code, font fallbacks).

## 2. The goal of the game (player-facing story)

Map is 16 columns x 11 rows. Coordinates are `(x, y)` with `(0,0)` top-left,
x increases right, y increases down. Hero starts at **(1, 0)**, 12 Movement Points
(MP) per turn.

| Quest | Goal | Teaches |
|-------|------|---------|
| 1 Starting Valley | Collect **1500 gold** (500 at (4,1) + 1000 chest at (2,5)) and pay the **Border Guard** at (7,3) | movement functions, coordinates |
| 2 Archmage's Loop Spell | Cross the river (column x=10) by **terraforming Bridges** with a `for` loop; reach the 2500-gold Dragon Hoard at (12,2) | `for` loops, `terraform()` |
| 3 Final Boss | Turn the mountain at (14,1) into grass, recruit **5 Green Dragons**, bridge the lava row (y=6), slay the **Black Dragon** at (14,9) | multi-turn planning, state |

**Victory** = commit a turn whose path touches the Boss with >= 5 dragons.
Engine sets `self.victory = True` and shows
"VICTORY on Day N! The Black Dragon is defeated! You are a Python Master!"

## 4. Player API (`hero_api.py`)

All functions only **append an action tuple** to `hero_api._actions`; nothing
moves until the engine simulates them.

| Function | Action tuple | Meaning |
|----------|--------------|---------|
| `move_right(n=1)` / `move_left(n=1)` | `("rel", +-n, 0)` | relative horizontal |
| `move_down(n=1)` / `move_up(n=1)` | `("rel", 0, +-n)` | relative vertical (down = +y) |
| `move_by(dx, dy)` | `("rel", dx, dy)` | relative vector |
| `move_to(x, y)` | `("abs", x, y)` | absolute target |
| `terraform(x, y, tile_type="B")` | `("terraform", x, y, "B")` | change a tile (upper-cased) |

`my_hero.py` imports them with `from hero_api import (...)` and must define
`plan_turn(gold, wood)`; return value is ignored.

### 4.1 In-Game Spell Console (primary input method, added 2026-10-22)

The bottom bar of the game window is now an **interactive Python console** (the
"Spell Console"). The child types commands directly in the game window instead
of editing `my_hero.py`. Commands accumulate per turn and preview updates live.

**Architecture:**
- `console_commands: list[str]` — accumulated commands for the current turn.
  Each Enter appends to this list. `run_console_preview()` replays ALL of them
  via `exec()` against a namespace containing the hero_api functions.
- Multi-line blocks (lines ending in `:`, like `for` / `if`) enter continuation
  mode (`console_in_block`). An empty Enter line ends the block and submits it
  as one command string.
- **Ctrl+Enter** = commit turn. Regular Enter = submit spell command.
- Special commands: `clear`, `undo`, `help`, `list`.
- **Tab completion** for function names.
- **↑/↓ arrow** = command history navigation.
- `my_hero.py` auto-reload still works when the console is empty (fallback).

**Keyboard shortcuts:**
| Key | Action |
|-----|--------|
| Enter | Execute typed spell / end multi-line block |
| Ctrl+Enter | Commit the turn |
| Ctrl+R | Reset map |
| Ctrl+G | Toggle grid |
| Ctrl+Z | Undo last spell |
| Ctrl+L | Clear console output |
| ↑ / ↓ | History navigation |
| Tab | Autocomplete command |
| Escape | Clear input / cancel block |
| F5 | Force reload my_hero.py |
| F11 | Toggle fullscreen |

Movement semantics (important, matches `run_preview` in engine.py):
- `rel` moves **horizontal first, then vertical** (all dx steps, then all dy steps).
- `abs` (`move_to`) also goes **X first, then Y**, from the *current simulated* position. It is not pathfinding; it walks an L-shape and fails if blocked.
- **All `terraform` actions are applied first** (pass 1 over `_actions`), regardless of where they appear in the function. So a terraform written after the `move_*` that needs it still works.
- Every turn starts from the hero's committed position; `plan_turn` is re-run from scratch each preview.

Objects are interacted with **automatically** when stepped on (also when the hero

isn't satisfied makes the whole preview invalid.

### Turn resolution
1. `run_preview()` (auto-triggered when `my_hero.py` mtime changes, or on key `P` / PREVIEW button): resets `hero_api`, reloads `my_hero` via `importlib.reload`, calls `plan_turn(gold, wood)`, builds `sim` dict, simulates tile by tile.
2. Invalid when: exception in the player's code ("Code Error: ..."), off the map, blocked tile, MP > 12, or an unmet guard/monster/boss. `sim["error"]` is shown in red; the path is drawn up to the failing tile.
3. `commit_turn()` re-runs the preview; if valid it applies terraforms to `self.grid`, moves hero to the last path tile, marks picked objects `Collected`, updates gold/wood/dragons, adds mine income for previously collected mines, increments `day`, writes `savegame.json`, runs the preview again.
4. Invalid turns do **nothing** (no day passes, nothing applied).

`sim` dict keys: `valid, path[(x,y,mp,ok_bool)...], terraforms[(x,y,type)...], expected_gold, expected_wood, expected_dragons, mp_used, error, picked_ids`.

### Controls
`Ctrl+S` in Thonny (auto-preview) · `Enter`/`Space` commit · `P` preview · `G` toggle grid/coords · `R` **reset and delete save** · `F11` fullscreen. Mouse buttons: PREVIEW, COMMIT TURN, GRID, RESET (`btn_*` rects in the engine).

## 6. Things an AI must know before editing

### 6.1 `hero_api.py` is overwritten on every launch
`engine.py` contains `HERO_API_CODE` and rewrites `hero_api.py` at import time.
**Edit the string in engine.py, not the file**, or your changes vanish. When adding a new API function, add it to `HERO_API_CODE`, handle its action tuple in `run_preview`, and add it to the import list in `my_hero.py`.

### 6.2 Type annotations on `sim` / `preview_data`
`sim` and `self.preview_data` are annotated `dict[str, Any]`. Without that, Pyrefly/Pylance infers a union of every value type and flags line ~692 (`for tx, ty, ttype in self.preview_data["terraforms"]`) with *"Cannot unpack tuple[...] (of size 4) into 3 values"* because `path` entries are 4-tuples and `terraforms` entries are 3-tuples. This is a **static-analysis false positive**, not a runtime bug. Keep the annotation (or move to a `TypedDict`).

### 6.3 Known quirks / possible improvements
- `terraform` can turn *any* tile into any letter for free (e.g. `terraform(x,y,'G')` on water or lava, no MP/gold cost, no limit). This is intended for the story ("Magic Bridge") but allows shortcuts, e.g. skipping bridges. Unknown letters are treated as blocked.
- The Guard doesn't physically block anything; it's purely a gold check. Walking around is impossible only because of the mountain wall.
- The Mage has no gameplay effect.
- Wood has no use yet (hook for future crafting/building lessons).
- Terraform coordinates outside the map are silently ignored.
- Monster `Guard_Power` column is loaded but not used in combat; the check is `dragons >= 1` (monster) and `dragons >= Value` (boss).
- The engine uses the global `hero_api._actions`, so `plan_turn` must not run concurrently.
- `savegame.json` stores grid, hero pos, resources, `collected_ids`; if `world_map.csv`/`map_objects.csv` are changed, **press R (or delete the save)** or old saves will overlay the old grid.

### 6.4 `extract_assets.py`
One-time tool; needs `Pillow` + `numpy` and reads generated sprite sheets from `~/.gemini/antigravity-ide/brain/8d828419-.../`. Output is already committed in `assets/`; you normally never run it. Sprites missing from `assets/` fall back to procedural art in `HDArtRenderer._build_hd_tiles`.

### 6.5 Rendering
`HDArtRenderer` (sprites + procedural fallbacks) and `TerrainRenderer` (terrain.py: seamless/hash-varied textures, auto-tiled roads, bridge orientation determined from neighbours/what it spans via `base_grid`, shoreline blending). The draw method overlays previewed terraforms on a **copy** of the grid so the bridge/road auto-tiling looks right before committing.

## 9. SPOILER: verified complete solution (4 turns, 4 days)

Verified by simulating the engine's rules against the real CSV files
(each turn <= 12 MP, all checks pass, ends at (14,9) with 5 dragons).

| Turn | Start | Code for `plan_turn` | MP | End | State after |
|------|-------|----------------------|----|-----|-------------|
| 1 | (1,0) | `move_right(3)` `move_down(1)` `move_left(1)` `move_down(4)` `move_left(1)` | 8.5 | (2,5) | gold 1500 |
| 2 | (2,5) | `move_to(3,3)` `move_right(9)` `terraform(10,3,'B')` `move_up(1)` | 10.5 | (12,2) | guard paid, gold 2500 |
| 3 | (12,2) | `terraform(14,1,'G')` `move_down(1)` `move_right(2)` `move_up(2)` | 5.0 | (14,1) | 5 dragons |
| 4 | (14,1) | `terraform(14,6,'B')` `move_to(14,9)` (or the loop from Quest 3's hint) | 8.0 | (14,9) | **VICTORY** |

Notes on the route:
- Turn 1 goes around the forest (1-2, 3-4): down column x=3, then left to the chest. The Gold Pile at (4,1) is picked on the way (row 0 -> down at x=4).
  The exact code above: right 3 along row 0 to (4,0), down 1 to (4,1) [+500], left 1 to (3,1), down 4 to (3,5), left 1 to (2,5) [+1000].
- Turn 2: `move_to(3,3)` (x first: (3,5)->(3,4)->(3,3)), `move_right(9)` runs along the road row y=3 through the guard bridge (7,3) [pays 1500], over the new bridge at (10,3), to (12,3); then up 1 to the Hoard (12,2) [+2500].
- Turn 3: mountain (14,1) -> grass, then down/right/up to avoid the mountain at (13,2) and reach the dragon cliff.
- Turn 4: Quest 3's hint suggests bridging the whole lava row with a loop (`for x in range(10, 16): terraform(x, 6, 'B')`), but only (14,6) is needed. Then `move_to(14,9)` walks straight down column 14 (8 MP).
- Alternative that saves a day: add `terraform(13,2,'G')` in Turn 3 and go (12,2)->(13,2)->(14,2)->(14,1) (3 MP) then straight down to the boss in the same turn (3 + 8 = 11 MP) for a **3-day** victory.
- Wood/Sawmill (6,1) and the Troglodytes (12,5) are optional.

### Quest completion flow

2. `execute_console_command` adds to `console_commands` and calls `run_console_preview`

5. `_interact_object` checks Act II guards via `_check_act2_guard` → runs quest check function
6. If guard passes, quest is added to `completed_quests`
7. `_trigger_zone_tips` shows Archmage Tip based on hero position
8. Sidebar shows quest checklist via `_build_act2_sidebar_scroll`
