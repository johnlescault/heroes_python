## ★ Player profile and confirmed decisions (from the parent, 2026-10-22)

**These override anything below that conflicts.**

| Topic | Decision |
|-------|----------|
| Player | Boy, **age 10**. Reads decently, **excellent at maths**. |
| Lesson length | **Short. It must feel like gameplay, not school.** |
| Battlefield | **Square grid** (no hexes). |

### What this means for design

**Short, gameplay-first lessons**
- One lesson = **1–3 in-game days, about 5–10 real minutes**. An Act = one evening or weekend session.
- **No lecture screens.** A concept is introduced by an in-game event: a Seer, a sign, a gate, or a monster. The event gives a **2-sentence max** "Archmage Tip" popup with **one** tiny code example. Then he plays.
- The `my_hero.py` template per lesson stays short. Show only the API he needs right now, and keep the hint comments to a few lines (no walls of text).
- Fail fast, retry fast: the preview shows the result on every save. Errors stay to 1 line of friendly text, plus the real error name and line number.
- Sphinx riddles are **optional bonus XP**, never blockers.
- Theory words ("boolean", "scope", "recursion") show up **after** he has already used the idea. Example: "You just used *recursion*! +1 Pathfinding." Name the concept as a reward, not as homework.

**Strong at maths, so lean in**
- Use real numbers: damage formulas, gold optimization, MP budgets, growth rates. Floats, `//`, `%` and `**` are all fair game from Act II.
- **Number systems early as side content:** scatter Obelisk / Dwarven-vault binary and hex puzzles as optional side quests from Act II onward. Act VII then becomes the "master" version (bitwise ops, XOR cipher) instead of the first exposure.
- Add **optimization challenges** (★★★ stars): "Recruit the strongest army possible with 5000 gold" (knapsack-lite), "reach the goal in the fewest MP", "win with the fewest losses". This is where a maths kid will shine and want to replay.
- Recursion (Act VI) can include maths-flavoured puzzles (Hydra growth, factorial Phoenix, Hanoi move counts `2**n - 1`). Let him **predict** the number before running the code.

**Square-grid battles** (see §4)
- 15 × 11 squares, **4-directional movement**, **Manhattan distance** (`abs(dx) + abs(dy)`). This is the same as the adventure map, so there's nothing new to learn about coordinates.
- Flying units ignore obstacles when moving. Shooters use Manhattan range with no line-of-sight in v1.

**Parent in the Hotseat** (see Act VIII and §4.6)
- The child's strategy goes in `duel_red.py` (project root, visible). The **parent's strategy** goes in `game_engine/.duels/parent_blue.py`, a hidden dotfolder the child won't browse to, loaded by the engine.
- **Draft phase:** both sides get the same gold budget (e.g. 5000) and draft an army with code or a menu. Maths optimization becomes part of the duel.
- **Handicap dial** so the parent can keep it close: extra starting gold for red, or a "Restraint" setting that limits blue's available units.
- After each duel, the engine can offer to **reveal the parent's code** as a reading exercise (parent's choice, toggle in config).
- Fallback opponents for when the parent is busy: built-in AI generals at 3 difficulty levels (*Squire*, *Knight*, *Warlord*), written in the same API. Defeating one unlocks reading its code.
- Duel history and leaderboard: `duels.json` (wins, losses, streaks, most efficient win).

## 0. Design pillars

1. **The concept must be the cheapest way to win.** Each lesson is set up so that
   hardcoding fails. Positions get randomized, prices change, or there are too many tiles
   to type by hand. The game then rewards the concept. Kids learn `for` loops because
   typing 40 `terraform()` calls is miserable.
2. **Heroes 3 flavour everywhere.** Every concept is dressed as a real H3 mechanic:
   Sphinx riddles, Keymaster tents, Obelisks and the Grail, 7 army slots, week growth,
   secondary skills, Hydras, the Subterranean Gate, Hotseat multiplayer, and so on.
3. **Concepts = Secondary Skills.** H3 heroes learn skills at Basic → Advanced → Expert.
   Each programming concept is a skill with those three ranks. Mastering a rank
   unlocks new `hero_api` functions or abilities, so learning has an in-game payoff.
4. **Plan → Preview → Commit loop stays.** It already works well. Battle mode reuses it:
   write the strategy, watch a preview simulation, then commit to the real fight.
5. **Friendly failure.** Every Python error is translated into a game message
   ("Your spell fizzled: line 12 tried to add words and numbers. Try `str()`!").
   Show the real error name and line too, so the child learns to read tracebacks.

## 2. Campaign structure

H3 shipped campaigns made of linked scenarios. We do the same: each **Act** is a new
map (new `world_map.csv` / `map_objects.csv` pair) with a story beat, a set of lessons
(quests), and a **boss challenge** that needs everything learned in that act.

```
Act I    The Starting Valley       (DONE)   calls, coordinates, intro loop
Act II   The Hero's Journal        (DONE)   comments, I/O, variables, types, constants, operators, casting, strings
Act III  The Shifting Sands        (DONE)   if / elif / else, boolean algebra   + Battle Tutorial
Act IV   Raising an Army                    lists, 2D lists, for, while          + Full Battle Mode
Act V    The Spellbook                      functions, return, scope, file I/O
Act VI   The Underground                    recursion
Act VII  The Grail                          bits, bytes, binary, hex, bitwise logic
Act VIII Armageddon's Blade (finale)        everything; final siege + Hotseat duels
```

Each lesson follows the same template:
- **Concept:** what is taught.
- **Hook:** the H3 mechanic that makes the concept necessary.
- **Quest:** what the child must do. The engine checks it automatically.
- **New API:** functions unlocked.
- **Engine check:** how we verify success. Where needed, we also verify that the concept
  was actually used, via `ast` inspection (section 6.4).
- **Sphinx riddle:** an optional quick quiz for a theory check and bonus XP.

## 3. Act-by-act lesson plan

### ACT II: The Hero's Journal
*Story:* The Archmage (already met in Act I) gives the hero a blank journal. "A true
hero keeps records, counts coins, and reads the signs of the land."

#### II-1 Comments: "The Scroll of Silence"
- **Hook:** A Seer's Hut hands over a **cursed scroll**: a pre-written `plan_turn` that
  marches the hero into lava. The child must silence the bad lines with `#` instead
  of deleting them. The Seer wants the scroll back intact.
- **Quest:** Reach the Seer with the cursed lines commented out, plus a comment above
  each group of moves explaining it ("# go around the forest").
- **Engine check:** `tokenize` the file. The cursed lines must still be present as
  comments, and there must be at least N comment lines. Award the **Scribe** badge.
- **Teach:** single-line `#`, inline comments, docstrings (`"""..."""`) on `plan_turn`,
  and that comments are for humans and ignored by Python.
- **Sphinx:** "What does Python do with a line that starts with `#`?"

#### II-2 Output: "The Hero's Log"
- **Hook:** A new sidebar panel, the **Hero's Log**, shows anything the child `print()`s.
  `say(text)` shows a speech bubble over the hero on the map.
- **Quest:** The Tavern keeper won't open the door until the hero *shouts* the password
  he wrote on the wall: `say("For Erathia!")`. Then `print()` the gold total at the
  start of the turn.
- **New API:** `say(text)`. Built-in `print` is redirected into the log panel.
- **Teach:** `print` with several arguments, `sep=`, `end=`, and the difference
  between `print` (log) and `say` (in-world).

#### II-3 Variables: "The Wandering Merchant"
- **Hook:** A merchant caravan **moves to a random spot every day**. A hardcoded
  `move_to(9, 4)` only works one day in many.
- **Quest:** `mx, my = scout("Merchant")`, then `move_to(mx, my)`. Repeat across 3 days.
- **New API:** `scout(name) -> (x, y)`. Also introduce the `hero` read-only object:
  `hero.x`, `hero.y`, `hero.mp`, `hero.name`.
- **Teach:** naming rules, assignment `=` vs comparison `==`, reassignment
  (`target_x = target_x + 1`), and multiple assignment / tuple unpacking.
- **Sphinx:** "After `a = 5` and `a = a + 2`, what is `a`?"

#### II-4 Data Types: "The Seven Resources"
- **Hook:** H3 has 7 resources: gold, wood, ore, mercury, sulfur, crystal and gems.
  Introduce them. Also show that MP can be `11.5` (a float), the hero's name is a `str`,
  and `hero.has_boat` is a `bool`.
- **Quest:** The **Sphinx** asks 4 riddles. The child answers with
  `answer_sphinx(value)`, and the value must be the right *type*. Example: "Give me a
  number with a point in it" accepts `3.5` but rejects `3` and `"3.5"`.
- **New API:** `answer_sphinx(value)`, `resources` dict (read-only), `type()` (built-in).
- **Teach:** `int`, `float`, `str`, `bool`, `None`, `type()`, plus a peek at `list`,
  `dict` and `tuple` (the Act I path tuples).

#### II-5 Constants: "The Laws of the Realm"
- **Hook:** Recruiting begins. The town posts prices. **On day 3 the King raises
  prices** ("Week of Taxes"). A child who typed `60` in five places has five bugs. A
  child who wrote `PIKEMAN_COST = 60` once fixes it in one line.
- **Quest:** Define `PIKEMAN_COST`, `ARCHER_COST` and `MAX_ARMY_SLOTS = 7` at the top of
  `my_hero.py`, and use them in all recruiting maths. Survive the price change.
- **Engine check:** `ast`: module-level UPPER_CASE names exist and are used at least twice.
- **Teach:** UPPER_CASE convention, why Python doesn't enforce it, and "magic numbers".
- **Bonus:** the engine exposes real constants from a read-only `realm` module:
  `realm.MAX_MP`, `realm.WEEK_LENGTH`.

#### II-6 Operators: "The Marketplace"
- **Hook:** Recruiting the most troops with limited gold, plus a Marketplace that
  trades resources at odd rates.
- **Quests:**
  - `recruit("Pikeman", gold // PIKEMAN_COST)`. The engine rejects requests you can't
    afford. Leftover gold = `gold % PIKEMAN_COST`.
  - The Marketplace trades 5 wood for 1 ore: compute what you get.
  - H3 week growth: dwellings produce new recruits each week, so `if day % 7 == 1`
    (previews Act III; here just compute it).
- **New API:** `recruit(unit, count)`, `trade(give, get, amount)`.
- **Teach:** `+ - * / // % **`, comparison `== != < > <= >=`, augmented `+=`, and
  precedence with parentheses.
- **Sphinx:** "17 gold, 5 per Pikeman. How many Pikemen and how much change?"

#### II-7 Type Casting: "The Merchant's Price Tags"
- **Hook:** Signs and scrolls in the world **return text**. `read_sign()` returns
  `"1500"`, not `1500`. Doing `gold >= read_sign()` makes Python complain.
- **Quest:** The Border Gate sign says how much it costs as text. Convert it with
  `int()`, compare, and pay. A second sign gives `"2.5"` MP cost, so use `float()`. Build
  a `say()` message that mixes text and numbers with `str()`, then with an f-string.
- **New API:** `read_sign() -> str`.
- **Teach:** `int()`, `float()`, `str()`, `bool()`, `round()`; what fails
  (`int("abc")`); truthiness (`bool(0)`, `bool("")`).
- **Engine nicety:** catch `TypeError` / `ValueError` and explain with an example fix.

#### II-8 Strings and Input: "The Keymaster's Riddles"
- **Hook:** H3 Keymaster Tents (coloured) give keys that open matching Border Gates.
  Here, the Keymaster gives a **scrambled password**.
- **Quests:**
  - `read_sign()` returns `"NOGARD"`, and the gate wants it reversed: `[::-1]`.
  - Seer cipher: `"the grail lies east"` must be shouted in UPPER CASE (`.upper()`).
  - Count the letters of the hero's name (`len()`). Take the first 3 letters (slicing).
  - `.split()` a sentence into words. Find a word with `in`.
- **New API:** `open_gate(password)`.
- **Input:** real `input()` blocks the game loop, so input is taught in **Tavern
  mini-games**. These are standalone scripts the child runs in Thonny's shell
  (`tavern/dice_game.py`, `tavern/name_your_hero.py`). Example: "Guess the dice roll,"
  where `input()` returns a string, so you must cast with `int()`. Tavern scores can
  unlock in-game rewards through a small `tavern_scores.json`.
- **Teach:** indexing, slicing, methods, f-strings, escape characters (`\n`), and
  immutability ("you can't change one letter, you make a new string").

**Act II Boss: "The Tax Collector."** Prices (constants) change, the gate amount comes
from a sign (casting), the password must be decoded (strings), and the hero must
recruit the maximum army (operators) and log a report (output).

### ACT III: The Shifting Sands (Decisions)
*Story:* A desert region where **things change every day**: monsters wander, oases dry
up, and sandstorms block tiles. Seeded randomness makes a single fixed plan impossible.

#### III-1 If / elif / else: "Week of the…"
- **Hook:** H3's random weekly events ("Week of the Pikeman: +growth"). Each day the
  engine picks an event. `today()` returns `"sandstorm"`, `"clear"` or `"festival"`.
- **Quests:**
  - `if today() == "sandstorm": move_by(0, 1) else: move_to(8, 2)`.
  - `look(x, y)` returns the tile letter / object type. A wandering monster spot must be
    avoided: `if look(5, 3) == "Monster": ...`.
  - `if gold >= COST: recruit(...) elif wood >= 10: trade(...) else: say("Saving up!")`.
- **New API:** `today()`, `look(x, y)`, `day`, `week`.
- **Teach:** indentation as blocks, `elif` chains, nested `if`, comparison operators.

#### III-2 Boolean Algebra: "Border Gates and Logic Shrines"
- **Hook:** Gates have *rules*. "The Red Gate opens if you hold the red key AND it is
  not night." "The Shrine of Air answers when (A or B) and not C."
- **Quests:**
  - `if has_key("red") and not is_night(): ...`
  - **Lever Shrine:** 3 levers. The shrine shows a rule like `(A and not B) or C`.
    The child sets `A`, `B` and `C` to `True` / `False` to make it `True`.
    Harder shrines want the rule to be `False`.
  - **Truth Table Tablet:** fill a truth table for `and`, `or`, `not` and `xor` as a
    nested list (previews Act IV). The engine checks it.
  - **De Morgan Sphinx:** "Is `not (A and B)` the same as `(not A) or (not B)`?"
    Prove it with a loop over all 4 combinations.
- **New API:** `has_key(color)`, `is_night()`, `set_levers(a, b, c)`.
- **Teach:** `and`, `or`, `not`, truth tables, De Morgan's laws, short-circuiting,
  and comparisons as booleans.

#### III-3 Battle Tutorial: "The Arena"
- First taste of **Battle Mode** (full spec in section 4). Only `if` statements are
  needed: one friendly stack (Pikemen) vs. one enemy stack.
- `def battle_turn(me, battle):` with
  `if battle.enemy_adjacent(me): return attack(...) else: return move_toward(...)`.
- Introduces the idea that **the game calls your function** (a callback). This is a
  stepping stone to Act V.

**Act III Boss: "The Sand Wyrm."** Random events, a gate with a compound boolean rule,
and a battle where `if` choices (defend vs attack vs wait) decide the result.

### ACT IV: Raising an Army (Lists and Loops) + Full Battle Mode
*Story:* War is coming. The hero must gather a real army and fight multi-stack battles.

#### IV-1 Lists: "The Seven Slots"
- **Hook:** H3 heroes carry exactly **7 army slots**. `hero.army` is a list of stacks.
- **Quests:**
  - Read `hero.army[0]`, find `len(hero.army)`, and recruit with `append` (the engine
    refuses an 8th slot).
  - Formation matters: slot order = starting battle rows. Put shooters at the back
    with `insert`, `pop` and `remove`.
  - Waypoints: `route = [(4, 1), (2, 5), (7, 3)]`, then visit with `move_to(*route[i])`.
- **New API:** `hero.army` (list of `Stack` views), `set_formation(list_of_names)`.
- **Teach:** indexing, negative indices, `len`, `append`, `insert`, `pop`, `remove`,
  `in`, slicing, `sorted(..., key=...)` (stretch), and lists vs tuples.

#### IV-2 2D Lists: "The Puzzle Map"
- **Hook:** `world = get_map()` returns the map as a list of rows: `world[y][x]`.
- **Quest:** Count all gold piles on the map, and find the nearest one. The engine
  scatters 15 piles randomly, so hand-typing is pointless.
- **Teach:** `grid[row][col]`, the y-before-x gotcha, and nested loops (bridge to IV-3).

#### IV-3 For loops (deep): "Bridges, Patrols and Head Counts"
- Act I introduced `for x in range(...)`. Now:
  - `for (x, y) in route: move_to(x, y)`
  - `for stack in hero.army: print(stack.name, stack.count)` (accumulator pattern:
    total army strength)
  - `for y in range(len(world)): for x in range(len(world[y])): ...` scanning the map
  - `enumerate`, `range(start, stop, step)`, `break`, `continue`
- **Quest:** "The Long River": bridge a river 40 tiles long, but only at shallow tiles
  where `look(x, y) == "w"` (shallow water). That combines a loop with an `if`.

#### IV-4 While loops: "Digging for Treasure"
- **Hook:** H3 heroes dig for the Grail. Here, `dig()` costs MP and has a chance to find
  treasure. `while hero.mp >= 1 and not found: found = dig()`.
- **Second hook:** Battle simulation: `while battle.enemies:` in a practice sandbox.
- **Engine requirement:** **infinite-loop protection** (section 6.2). A runaway loop
  shows "Your hero fell into an endless dream… (loop ran 100,000 times)".
- **Teach:** condition-controlled vs count-controlled loops, sentinels, `break`, and
  how to avoid infinite loops.

#### IV-5 Full Battle Mode unlocked
- Multi-stack battles with lists of allies and enemies. See section 4. The classic
  "find the weakest enemy" loop becomes the child's first real tactic.

**Act IV Boss: "The Troglodyte Warren."** The existing Troglodytes (ID 7) become a real
battle: 5 enemy stacks vs your 7 slots. Requires a loop over enemies, a formation list,
and a `while` digging side quest for the gold to recruit.

### ACT V: The Spellbook (Functions and Scope)
*Story:* The Archmage teaches the hero to **write their own spells**. Every `def` in
`my_hero.py` appears in the hero's Spellbook panel with its docstring as description.

#### V-1 Functions: "Your First Spell"
- **Hook:** Repeated move patterns become spells.
  `def build_bridge(x, y_start, y_end):` (loop inside), then call it 3 times for 3 rivers.
- **Quest:** a map with 3 rivers of different lengths. A child without functions copies
  the loop 3 times; the **Spell Efficiency** star rewards functions.
- **Teach:** `def`, parameters vs arguments, default parameters, docstrings, and
  calling before defining (error).

#### V-2 Return values: "Spells That Answer"
- `def distance(x1, y1, x2, y2): return abs(x1 - x2) + abs(y1 - y2)`
- `def weakest(enemies): ... return best`
- **Quest (battle):** split `battle_turn` into helpers: `choose_target()`,
  `should_defend()`. Each helper is tested separately by the **Spell Trials** (unit
  tests the engine runs with known inputs, shown as glowing runes ✓/✗).
- **Teach:** `return` vs `print`, `None` when you forget to return, and functions calling
  functions.

#### V-3 Scope: "Dimension Door"
- **Hook:** H3's *Dimension Door* spell. "What happens inside a spell stays inside the
  spell." Variables created in a function vanish when it ends.
- **Quests:**
  - **Bug hunt:** a pre-written spell tries to count gold inside a function and print it
    outside, which raises `NameError`. Fix it with `return`.
  - **The Forgetful Hero:** `my_hero.py` is reloaded on every save, so module-level
    variables reset each preview/turn. To remember across days, use the engine's
    `memory` dict (persisted in the save). This teaches object lifetime vs scope.
  - **The Forbidden Rune (`global`):** using `global` works but costs 1 mana and the
    Archmage frowns. It teaches that `global` exists and why returning values is cleaner.
  - **Shadowing:** a parameter named `gold` hides the outer `gold`. Predict the output.
- **New API:** `memory` (dict, persisted).
- **Teach:** local vs global, the LEGB lookup order (simplified), parameters as local
  variables, and `global`.

#### V-4 File Input/Output: "Seer's Scrolls"
- **Hook:** Seer's Huts drop real text files in `scrolls/` (e.g. `scrolls/seer_3.txt`).
  The child reads them with `open()`. The hero's **Chronicle** is written with
  `open("chronicle.txt", "a")`.
- **Quest:** a scroll lists 10 treasure coordinates, one per line, as text. Read the
  lines, `split(",")`, cast with `int()`, and visit them with a loop and function.
- **Teach:** `open`, `with`, `read`, `readlines`, `write`, modes `r` / `w` / `a`, and
  `strip()`.

**Act V Boss: "The Necromancer's Riddle Tower."** Each floor is a spell trial (a
function with expected inputs/outputs). Climb by writing correct functions, then win a
battle using a strategy built only from your helper spells.

### ACT VI: The Underground (Recursion)
*Story:* A Subterranean Gate (H3's two-level maps) leads below ground into darkness.

#### VI-1 Recursion: "The Labyrinth"
- **Hook:** An underground maze where `look()` only works on adjacent tiles. The engine
  provides `explore_step(x, y)`.
- **Quest:** write `def explore(x, y, visited):` that calls itself in 4 directions,
  with base cases for wall, visited, or out of map. It finds the Minotaur's hoard.
- **Visual:** each recursive call lights a torch. Returning extinguishes it. The **call
  stack** is drawn as a stack of scrolls in the sidebar (huge teaching value).
- **Failure:** missing base case leads to `RecursionError`, shown as "Lost forever in
  the Labyrinth. Did you forget when to STOP?"
- **Teach:** base case and recursive case, the call stack, and that recursion and loops
  can solve the same problems.

#### VI-2 Recursion in battle: "The Hydra"
- **Hook:** H3 Hydras. Variant rule: each time a Hydra head is cut, 2 smaller heads grow
  until size 0. "How many strikes to kill a size-4 Hydra?"
- **Quest:** `def strikes(size): if size == 0: return 1; return 1 + 2 * strikes(size - 1)`.
  The answer decides how many Archers to bring into the battle.
- Also **Phoenix rebirth** = factorial, as a Sphinx riddle.

#### VI-3 Recursion puzzle: "The Three Obelisks" (Towers of Hanoi)
- Move a stack of magic rings between 3 obelisks; a bigger ring can't sit on a smaller.
  `def hanoi(n, src, dst, via):` calls `move_ring(src, dst)`. The engine animates it.
  The ring count grows (3 → 5 → 8) so that solving by hand becomes impossible.

**Act VI Boss: "The Dungeon Overlord."** Navigate an unknown maze recursively, then fight
a Hydra stack whose growth you must predict with a recursive function.

### ACT VII: The Grail (Bits, Bytes, Binary, Hex, Bitwise Logic)
*Story:* H3's Grail: Obelisks reveal pieces of a puzzle map, and the Grail lies where
you dig. The Dwarven keepers encode everything in **binary and hex**.

#### VII-1 Bits and Bytes: "The Eight Obelisks"
- **Hook:** 8 Obelisks in a row. Each is lit (1) or dark (0). Together they form **one
  byte**. That's 2^8 = 256 possible patterns.
- **Quests:**
  - Visit Obelisks to toggle them. The pattern must match a rune on the vault.
  - Spellbook capacity: a spell scroll holds **16 bytes** of name, so the child must
    pick a spell name whose `len(name.encode("utf-8"))` fits (an emoji takes 4 bytes!).
- **Teach:** bit, nibble (4 bits), byte (8 bits), KB/MB, 2^n combinations, and text as
  bytes (UTF-8).

#### VII-2 Binary Numbers: "The Dwarven Vault"
- **Quests:**
  1. The vault shows obelisk pattern `10101101`. Enter the decimal code (173). First by
     hand on paper (place values 128 64 32 16 8 4 2 1), then with `int("10101101", 2)`.
  2. Reverse: the vault wants 200, so light the right obelisks with `bin(200)`.
  3. **Write your own** `to_binary(n)` with a loop (`n % 2`, `n // 2`), then again
     recursively. This reuses Acts IV and VI.
- **Teach:** base 2, place values, `bin()`, `int(s, 2)`, `0b` literals, and counting
  in binary.

#### VII-3 Hexadecimal: "Crystal Banners and the Grail Coordinates"
- **Hook 1:** Banner dyes are colours like `#FF8800`. Each pair is a byte (R, G, B).
  The Crystal Cavern wants the banner dyed an exact colour, so the child must
  build the hex string from numbers: `f"#{r:02X}{g:02X}{b:02X}"`.
- **Hook 2:** Puzzle-map pieces reveal Grail coordinates **in hex**: `0x0E, 0x09`, which
  is (14, 9). Convert and dig there.
- **Teach:** base 16, 1 hex digit = 1 nibble = 4 bits, `hex()`, `int(s, 16)`,
  `0x` literals, and why programmers like hex (compact binary).

#### VII-4 Bitwise Boolean Algebra: "Schools of Magic"
- **Hook:** H3 has 4 magic schools. Give each a bit: AIR=1, EARTH=2, FIRE=4, WATER=8.
  Units have immunity masks. Black Dragons are immune to all magic, so the mask is
  `0b1111`.
- **Quests:**
  - Can my Fireball hurt this unit? `if not (unit.immune & FIRE): cast(...)`
  - Combine schools: `my_schools = AIR | FIRE`.
  - **Grail cipher:** the final map piece is XOR-encrypted (`^`) with the obelisk byte
    from VII-1. Decrypt it to get the true dig spot.
  - Shifts: `1 << 3 == 8` ("the 4th obelisk").
- **Teach:** `& | ^ ~ << >>`, links back to truth tables in III-2, and bitmasks/flags.
- **New API:** `AIR, EARTH, FIRE, WATER` constants, `unit.immune`, `cast(spell, target)`.

**Act VII Boss: "Raising the Grail."** Collect obelisk bits, decode hex coordinates, XOR
the cipher, dig the Grail, and build it in town. This grants the finale's super-unit.

## 4. Battle Mode specification

### 4.1 Overview
- Triggered when the hero steps on a Monster/Boss/enemy Hero (replaces today's simple
  "need N dragons" checks in `_interact_object`).
- The screen switches to a **battlefield**: 15 × 11 **square** tiles (confirmed: no hexes).
  4-directional movement with Manhattan distance, same as the adventure map.
- Fully automated by the child's code: the engine calls
  `battle_turn(me, battle)` for each friendly stack's turn. The return value is the action.
- **Preview** = a simulated battle with the same seed, shown as a fast replay with a
  win/lose forecast. **Commit** = the real battle (same seed, so results match: fair
  and debuggable).
- Hero can cast **one spell per round** via `hero_spell(battle)` (optional function).

### 4.2 Units (simplified, H3-inspired; tune freely)
| Unit | Atk | Def | Dmg | HP | Speed | Traits | Cost |
|------|-----|-----|-----|----|-------|--------|------|
| Pikeman | 4 | 5 | 1–3 | 10 | 4 | | 60g |
| Archer | 6 | 3 | 2–3 | 10 | 4 | shooter (12 shots) | 100g |
| Griffin | 8 | 8 | 3–6 | 25 | 6 | flying, 2 retaliations | 200g |
| Swordsman | 10 | 12 | 6–9 | 35 | 5 | | 300g |
| Monk | 12 | 7 | 10–12 | 30 | 5 | shooter | 400g |
| Cavalier | 15 | 15 | 15–25 | 100 | 7 | | 1000g |
| Angel | 20 | 20 | 50 | 200 | 12 | flying | 3000g + 1 gem |
| Green Dragon | 18 | 18 | 40–50 | 180 | 10 | flying, breath attack | dwelling |

### 4.3 Rules (H3-flavoured, kid-sized)
- **Stacks:** one unit type × count. Damage kills top units first; the top unit keeps
  partial HP (`stack.count`, `stack.top_hp`).
- **Initiative:** each round, stacks act in order of speed (ties alternate sides).
- **Actions:** `move(x, y)`, `attack(target)` (moves adjacent and strikes),
  `shoot(target)`, `defend()` (+30% defence until next turn), `wait()` (act later in
  the round).
- **Retaliation:** a stack strikes back once per round (Griffins twice).
- **Shooters:** half damage in melee, and can't shoot if an enemy is adjacent.
- **Damage formula** (good for operators, floats and casting):
  ```python
  base = count * randint(dmg_min, dmg_max)
  if atk > dfn: base *= 1 + 0.05 * min(atk - dfn, 60)
  else:         base *= 1 - 0.025 * min(dfn - atk, 28)
  damage = int(base)
  ```
- **Morale/Luck** (stretch): random bonus actions or double damage, taught as
  probability with `random` in the Tavern.
- **Movement:** 4-directional, Manhattan distance. `speed` = max tiles per turn.
  Walkers path around obstacles (the engine does BFS for `attack()` / `move_toward()`).
  Flyers ignore obstacles.

### 4.4 Read-only API given to `battle_turn`
```python
me.name, me.count, me.hp, me.top_hp, me.attack, me.defense,
me.speed, me.x, me.y, me.is_shooter, me.shots, me.is_flying, me.immune

battle.allies          # list of stacks
battle.enemies         # list of stacks
battle.round           # int
battle.distance(a, b)  # tiles
battle.can_shoot(me)   # bool (shooter, has shots, not blocked)
battle.adjacent_enemies(me)  # list
battle.tile(x, y)      # "." open, "#" obstacle, "~" moat
```
Views must be **immutable copies** (frozen dataclasses), so the child can't set
`enemy.count = 0`. This could be a fun Easter egg message: "Nice try, the Black Dragon
laughs at your hacking."

### 4.6 Hotseat duel flow (child vs parent)
1. **Draft:** both sides get `DUEL_BUDGET` gold (default 5000, plus red's handicap bonus).
   Each side defines `def draft(budget, shop):` returning a list of `(unit, count)`,
   max 7 slots. The engine validates the cost.
2. **Deploy:** the formation is the order of the draft list. Red deploys on the left
   columns, blue on the right.
3. **Battle:** the engine alternates `battle_turn` calls from `duel_red.py` and
   `.duels/parent_blue.py` by initiative. Same seed for preview and real fight.
4. **Result:** a replay is saved to `duels/replays/` (step-through viewer).
   `duels.json` records W/L, streak and efficiency (losses taken).
5. **Config** (`game_engine/.duels/config.json`): `handicap_gold`,
   `blue_banned_units`, `reveal_parent_code_after_duel`, `seed_mode`
   (`fixed` / `random`).
- If `.duels/parent_blue.py` is missing, fall back to the built-in *Squire* AI.

### 4.5 Example child strategy (end of Act V)
```python
def weakest(enemies):
    best = enemies[0]
    for e in enemies:
        if e.hp < best.hp:
            best = e
    return best

def battle_turn(me, battle):
    target = weakest(battle.enemies)
    if battle.can_shoot(me):
        return shoot(target)
    if me.is_shooter and battle.adjacent_enemies(me):
        return defend()
    return attack(target)
```

## 6. Engine work required (technical roadmap)

### 6.1 Campaign/quest data system
- Folder per act: `campaign/act2/world_map.csv`, `map_objects.csv`, `quest.json`.
- `quest.json`: story text, objectives (machine-checkable), unlocked API names, required
  concept checks, Sphinx riddles, rewards, next act.
- Save file gains: `act`, `quest_id`, `skills`, `xp`, `stars`, `memory`,
  `save_version` (migrate old saves).

### 6.2 Safe execution of the child's code (needed before `while` loops)
- Today `plan_turn` runs in-process on the pygame thread, so an infinite loop freezes
  the window.
- Run player code in a **subprocess** (or a worker thread plus `sys.settrace` with a
  line budget) with a timeout of ~2 s / 100k lines. Kill it and show the "endless
  dream" message.
- Capture `stdout` (redirect `print`) into the Hero's Log.
- Catch exceptions, then map them to friendly text plus the real error name and line.

### 6.3 API gating
- Generate `hero_api.py` from a registry: `{name: (func, unlocked_by_skill)}`.
- Calling a locked function raises a friendly error: "You haven't learned *Expert
  Logistics* yet!" (Remember: `hero_api.py` is regenerated by `engine.py`. See
  `.AI_HANDOFF.md` §6.1.)

### 6.4 Concept verification with `ast`
- Example checks: `has_for_loop`, `has_while`, `defines_function(name)`,
  `function_is_recursive(name)`, `uses_constant_names`, `uses_bitwise_op`,
  `comment_count >= n` (via `tokenize`).
- Use this only for the ★★★ star or for required lessons. Be gentle, and offer a hint
  instead of a hard block.

### 6.5 New modules
